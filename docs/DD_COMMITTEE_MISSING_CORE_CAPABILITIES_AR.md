## 1) معيار الإدراج في هذا التقرير

تُدرج القدرة هنا فقط إذا تحقق الثلاثة معاً:

1. مطلوبة معيارياً لمشتري مؤسسي أو مستثمر جاد في فئة قرار/ثقة مالية.
2. غير موجودة كمنتج حيّ / برنامج تشغيلي مكتمل — أو موجودة كوثيقة/stub فقط.
3. غيابها يمنع أو يؤخر LOI / procurement / diligence إغلاق.

**لا يُدرج هنا:** أفكار تفوق تنافسي اختيارية (F1–F10 من دراسة السوق) — تلك فرص نمو وليست table-stakes.

## 3) القدرات الناقصة — P0 (حاجز صفقة)

### C-P0-01 — Enterprise SSO مؤسسي (SAML 2.0 / OIDC enterprise / Okta / Azure AD)
| الحقل | المحتوى |
|---|---|
| **الواجب** | تسجيل دخول مؤسسي عبر IdP العميل مع JIT provisioning و SCIM اختياري |
| **الوضع الحالي** | OAuth مستهلك (Google/Apple/GitHub) + جلسة محلية — **ليس** SSO مؤسسي |
| **الدليل** | لا مسار SAML/OIDC enterprise في سطح auth المنتج |
| **لماذا أساسية** | أغلب مشتري B2B يمنعون حسابات شخصية/consumer OAuth |
| **معيار الإغلاق** | تكامل Okta أو Azure AD حيّ + دليل إعداد عميل + اختبار login مؤسسي |

### C-P0-02 — MFA إلزامي على مستوى المنظمة (Enforced org MFA)
| الحقل | المحتوى |
|---|---|
| **الواجب** | سياسة MFA إلزامية لكل أعضاء org (TOTP/WebAuthn) مع منع login بدونها |
| **الوضع الحالي** | TOTP اختياري للمستخدم الفردي فقط |
| **لماذا أساسية** | متطلبات أمن مشترٍ / SOC2-aligned access control |
| **معيار الإغلاق** | Admin يفعّل `org.require_mfa=true` ويُرفض أي جلسة بدون عامل ثانٍ |

### C-P0-03 — عزل متعدد المستأجرين (Multi-tenant org isolation)
| الحقل | المحتوى |
|---|---|
| **الواجب** | نموذج Org → Members → Roles → بيانات معزولة مع منع التسريب cross-tenant |
| **الوضع الحالي** | منتج موجّه أساساً لحساب فردي/جلسة؛ لا tenant model مؤسسي مكتمل |
| **لماذا أساسية** | بدونها لا يُباع Desk/Institutional لفريق |
| **معيار الإغلاق** | جداول org + اختبارات عزل + API scoped بـ `org_id` |

### C-P0-04 — مسار دفع حيّ + KYC/AML تشغيلي (Live paid rail)
| الحقل | المحتوى |
|---|---|
| **الواجب** | اشتراك مدفوع حقيقي عبر PSP مع فواتير و KYC عند الحاجة وحدود AML |
| **الوضع الحالي** | كود Stripe/PayPal/crypto موجود؛ **لا** مفاتيح إنتاج؛ 0 مدفوعين؛ KYC stub |
| **لماذا أساسية** | لا إيراد = لا إثبات willingness-to-pay = ضعف استثمار |
| **معيار الإغلاق** | أول فاتورة حقيقية + webhook موقع + سياسة KYC منشورة ومطبّقة |

### C-P0-05 — SLA تعاقدي موقع + دليل سعة موقّع تحت حمل
| الحقل | المحتوى |
|---|---|
| **الواجب** | وثيقة SLA ملزمة + صف إثبات حمولة موقّع (RPS/p95/error) من staging/prod |
| **الوضع الحالي** | أهداف داخلية + قوالب؛ HUMAN_OPS يمنع الإغلاق؛ لا صف موقّع |
| **لماذا أساسية** | المشتري المؤسسي يشتري التزاماً لا وعداً |
| **معيار الإغلاق** | MSA/SLA موقع + صف `signed_capacity_row` حيّ |

### C-P0-06 — شهادات امتثال خارجية (SOC 2 / ISO 27001 أو ما يعادلهما للمشتري)
| الحقل | المحتوى |
|---|---|
| **الواجب** | تقرير SOC 2 Type I على الأقل أو ISO 27001، أو خطاب رسمي بمسار زمني ملزم |
| **الوضع الحالي** | ضوابط داخلية + security hardening — **ليست** شهادة |
| **لماذا أساسية** | بوابة vendor security لمعظم المؤسسات |
| **معيار الإغلاق** | تقرير مدقق أو خطاب auditor بجدول واضح |

### C-P0-07 — اختبار اختراق طرف ثالث + خطاب إصلاح
| الحقل | المحتوى |
|---|---|
| **الواجب** | Pentest سنوي من جهة مستقلة + remediation letter |
| **الوضع الحالي** | غير موجود كدليل خارجي |
| **لماذا أساسية** | مطلوبة في معظم security questionnaires |
| **معيار الإغلاق** | تقرير pentest + إثبات إغلاق Critical/High |

### C-P0-08 — عقود بيانات وترخيص حقيقية (MSA / DPA / Data License) قابلة للتوقيع
| الحقل | المحتوى |
|---|---|
| **الواجب** | حزم عقود: MSA + DPA + ترخيص بيانات المصدر + حدود إعادة التوزيع |
| **الوضع الحالي** | وثائق/قوالب داخل المستودع — ليست عقوداً موقّعة مع موردين/عملاء |
| **لماذا أساسية** | بدونها المخاطر القانونية تمنع الشراء المؤسسي |
| **معيار الإغلاق** | قوالب محامٍ معتمدة + مسار توقيع إلكتروني + أول DPA موقّع |

## 4) القدرات الناقصة — P1 (حاجز procurement)

### C-P1-01 — RBAC مؤسسي بأدوار مشترٍ (Analyst / PM / Compliance / Admin)
| الحقل | المحتوى |
|---|---|
| **الواجب** | أدوار وصلاحيات دقيقة على مستوى org مع audit على تغيير الدور |
| **الوضع الحالي** | أدوار موثّقة جزئياً؛ التنفيذ المنتج غير مكتمل كـ org RBAC |
| **معيار الإغلاق** | مصفوفة صلاحيات حيّة + اختبارات منع الوصول |

### C-P1-02 — Model Card موجّه للمشتري (Buyer-facing Model Card)
| الحقل | المحتوى |
|---|---|
| **الواجب** | بطاقة نموذج عامة: حدود الأداء، التحيز، نطاق التغطية، حالات الفشل، نسخة النموذج |
| **الوضع الحالي** | لا Model Card مشترٍ منفصل؛ الشفافية موزعة على صفحات متفرقة |
| **معيار الإغلاق** | صفحة `/model-card` عامة + PDF قابل للجنة |

### C-P1-03 — برنامج استجابة حوادث (Incident Response) مع RACI وجدول إبلاغ
| الحقل | المحتوى |
|---|---|
| **الواجب** | خطة IR، أصحاب أدوار، قنوات إبلاغ عملاء، postmortem إلزامي |
| **الوضع الحالي** | stubs/وثائق جزئية — ليس برنامجاً تشغيلياً مثبتاً |
| **معيار الإغلاق** | جدول تمرين tabletop واحد على الأقل + قالب إبلاغ عميل |

### C-P1-04 — WAF / CDN / حماية حافة إنتاجية
| الحقل | المحتوى |
|---|---|
| **الواجب** | طبقة حافة (Cloudflare/AWS WAF أو مكافئ) مع rate/geo/bot controls |
| **الوضع الحالي** | غير مثبت كقدرة إنتاج موثّقة في المسار الحالي |
| **معيار الإغلاق** | سياسة WAF حيّة + دليل إعداد + اختبار حظر |

### C-P1-05 — تفعيل HA إنتاجي موقّع (ليس كوداً فقط)
| الحقل | المحتوى |
|---|---|
| **الواجب** | Postgres HA + Redis + replicas + failover drill موثّق |
| **الوضع الحالي** | الكود/التركيب جاهز جزئياً؛ Soft Launch على SQLite؛ لا drill موقّع |
| **معيار الإغلاق** | بيئة HA حيّة + محضر failover + مقاييس |

### C-P1-06 — قابلية ملاحظة إنتاجية كاملة (Tracing + Error budget + Customer status)
| الحقل | المحتوى |
|---|---|
| **الواجب** | Distributed tracing + SLO/error budget + صفحة حالة للعملاء |
| **الوضع الحالي** | مقاييس/سجلات جزئية؛ لا برنامج observability مؤسسي مكتمل |
| **معيار الإغلاق** | tracing على المسارات الحرجة + status page عامة |

### C-P1-07 — إدارة مفاتيح وأسرار مؤسسية (Secrets manager + rotation)
| الحقل | المحتوى |
|---|---|
| **الواجب** | خزّان أسرار (Vault/ASM/GCP SM) + دوران مفاتيح + فصل بيئات |
| **الوضع الحالي** | اعتماد `.env`/بيئة محلية؛ لا برنامج دوران مثبت |
| **معيار الإغلاق** | أسرار الإنتاج خارج المستودع + سياسة دوران موثّقة ومطبّقة |

## 5) القدرات الناقصة — P2 (نضج تشغيلي متوقع)

### C-P2-01 — بيئة Staging مرآة لـ Production
| الحقل | المحتوى |
|---|---|
| **الواجب** | Staging بنفس طبولوجيا الإنتاج لاختبارات الحمل والإصدارات |
| **الوضع الحالي** | غير مثبت كمرآة كاملة؛ يمنع صف السعة الموقّع |
| **معيار الإغلاق** | staging URL + نفس stack + بيانات اصطناعية آمنة |

### C-P2-02 — برنامج نسخ احتياطي واستعادة مختبر (Backup/Restore drill)
| الحقل | المحتوى |
|---|---|
| **الواجب** | نسخ مجدولة + استعادة مختبرة برقم RPO/RTO |
| **الوضع الحالي** | غير مثبت كقدرة مكتملة في Soft Launch |
| **معيار الإغلاق** | محضر استعادة ناجح بتاريخ + مدة |

### C-P2-03 — دعم عملاء بمستويات استجابة (Support tiers / SLA tickets)
| الحقل | المحتوى |
|---|---|
| **الواجب** | قنوات دعم + أولويات + أوقات استجابة حسب الخطة |
| **الوضع الحالي** | غير مبني كمنتج دعم مؤسسي |
| **معيار الإغلاق** | نظام تذاكر + سياسة استجابة منشورة |

### C-P2-04 — بوابة مطورين / SDK رسمي مستقر لإشارات القرار
| الحقل | المحتوى |
|---|---|
| **الواجب** | SDK + أمثلة + versioning + deprecation policy لـ API القرار |
| **الوضع الحالي** | APIs موجودة؛ لا SDK رسمي متعدد اللغات كمنتج |
| **معيار الإغلاق** | SDK واحد على الأقل (Python أو JS) + دليل + semver |

### C-P2-05 — كتالوج تغطية مؤسسي قابل للتعاقد (Contractable coverage catalog)
| الحقل | المحتوى |
|---|---|
| **الواجب** | قائمة أسواق/أزواج مغطاة تعاقدياً مع التزام تحديث وحدود |
| **الوضع الحالي** | Coverage Honesty يكشف الفجوة؛ لا كتالوج تعاقدي |
| **معيار الإغلاق** | ملحق تغطية في العقد + تحديث ربع سنوي |

### C-P2-06 — برنامج جودة بيانات Continuity (Data QA / freshness SLO)
| الحقل | المحتوى |
|---|---|
| **الواجب** | SLO لحداثة البيانات + إنذار عند الانقطاع + owner لكل مصدر |
| **الوضع الحالي** | freshness موجود جزئياً؛ ليس برنامجاً مؤسسياً بـ owner/SLO |
| **معيار الإغلاق** | لوحة freshness + إنذار + RACI مصادر |

## 6) قدرات موجودة جزئياً — لا تُحسب «موجودة» حتى تكتمل

| القدرة | الموجود | الناقص لإعلان «متوافرة» |
|---|---|---|
| Auth | جلسات + OAuth مستهلك + TOTP اختياري | SSO + MFA إلزامي org |
| Payments | موصلات كود | مفاتيح إنتاج + أول إيراد + KYC حي |
| Trust surfaces | Kill-Rate / Miss Feed / Coverage Honesty / Arena… | Model Card مشترٍ موحّد |
| Security controls | Headers / CSRF / rate / audit جزئي | SOC2 + pentest + WAF + secrets manager |
| HA design | كود/docs / compose | تفعيل إنتاج + drill موقّع |
| Legal packs | قوالب داخل المستودع | عقود محامٍ + توقيع فعلي |
| Observability | مقاييس أساسية | tracing + status page + error budget |
| Org model | إشارات وثائقية | tenant isolation + RBAC حي |

## 9) خلاصة لجنة القدرات الناقصة

BLACKDARK يملك **سطحاً منتجياً قوياً للثقة والقرار**، لكن تنقصه حزمة القدرات المؤسسية الأساسية التي يفترضها المشتري والمستثمر قبل التوقيع:

1. **هوية وتنظيم:** SSO + MFA إلزامي + multi-tenant + RBAC  
2. **إيراد وامتثال تجاري:** دفع حيّ + KYC + عقود MSA/DPA  
3. **التزام تشغيلي:** SLA موقع + سعة موقّعة + HA حيّ + IR  
4. **ثقة خارجية:** SOC2/ISO + pentest + Model Card مشترٍ  
5. **بنية تحتية أمنية:** WAF + secrets manager + observability  

**حكم اللجنة:** المنتج يمكنه إثبات «قيمة قرار وشفافية» اليوم؛  
**لا يمكنه بعد** إثبات «جاهزية مؤسسية للشراء والتعاقد» حتى تُغلق موجة P0 على الأقل.
