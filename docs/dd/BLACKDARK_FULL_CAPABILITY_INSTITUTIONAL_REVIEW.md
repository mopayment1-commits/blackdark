# BLACKDARK — المراجعة المؤسسية الشاملة للقدرات (المراجعة الثانية)

**المنتج:** BLACKDARK Trust OS  
**الفرع:** `cursor/95plus-recert-phase0-120d`  
**مصدر الجرد الآلي:** `GET /api/product/capability-inventory` (`product_capability_inventory.py`)  
**مصدر الشرائح الست:** `GET /api/trial/persona-readiness`  
**أدلة الحواجز الأربعة:** `docs/dd/BLACKDARK_FOUR_BLOCKERS_EVIDENCE.json`  
**الحكم الملزم:** **NOT COMPLETE**  
**جاهزية التجربة بلا دفع:** نعم (ورقي / إثبات)  
**جاهزية المال الحي:** لا  

هذا التقرير هو **المراجعة الثانية الدقيقة** بعد تقرير جاهزية الشرائح الست. التقرير السابق غطّى الاستحقاق حسب الجمهور ولم يحصر كل قدرة في كل مجال. هذا المستند يردّ على النقاط الثماني المطلوبة بالكامل، بندًا بندًا، دون ادّعاء اكتمال مؤسسي.

### قواعد الصدق الملزمة (لا تُخالف)

- الاختبار الأخضر ≠ اكتمال المنتج.
- `synthetic_mid` ≠ كتاب L2 مؤسسي.
- توقيع محفظة محلي ≠ تحقق على السلسلة (Jupiter VC).
- HA محلي لـ Postgres ≠ cloud multi-AZ.
- تعبئة ورقية ≠ `live_fill`.
- الإغلاق بالخطة (`gated`) ≠ عطل.
- الحاجز الخارجي (`external_block`) ≠ عيب منتج داخلي.
- لا يُعلن `COMPLETE` / `live_fill=true` / L2 100% / cloud HA بدون دليل غرفة نظيفة على نفس SHA.

حالات القدرة المستخدمة في الجرد:

| الحالة | المعنى |
|---|---|
| `works` | المسار موجود ويعمل ضمن سقف عدم الدفع |
| `partial` | الكود موجود لكن الجودة/العمق أو الاعتماد التشغيلي ناقص بصدق |
| `gated` | يعمل لمن له الاستحقاق؛ المغلق بالخطة ليس عطلًا |
| `external_block` | المسار مسلّح؛ الإغلاق خارج المنتج (جغرافيا / تمويل / سحابة مدفوعة) |
| `ops_config` | يحتاج سرًا أو إعدادًا من المالك (PSP، بريد، OAuth، تيليغرام) |

## 2) مراجعة دقيقة لكل جزء وكل قدرة وكل ميزة

المراجعة هنا ليست قائمة تسويق. لكل مجال: ماذا يعمل، ماذا جزئي، وما الذي لا يجوز وعده.

### 2.1 الهوية

- التسجيل/الجلسة/MFA **تعمل**. مسار `/settings/security` كان 404؛ أصبح تحويل 307 إلى `/profile` حيث التسجيل الفعلي لـ TOTP. لا مسار MFA ضائع.
- OAuth والبريد **ليسا معطّلين برمجيًا**؛ هما `ops_config`. بدون أسرار المالك لا يكتمل الدخول الاجتماعي أو بريد الإنتاج. هذا نقص تشغيلي لا عطل كود.
- بوابات الطبقة تُفرض على واجهات الأوركل/الأربتراج/التنبيهات/الدردشة/المحفظة. المغلق للمجاني مقصود.

### 2.2 الفوترة

- الكتالوج والحالة **يعملان** ويعرضان الأسعار بصدق.
- Checkout **جزئي**: المسار والكود جاهزان؛ الشحن الحي يحتاج أسرار Stripe/Lemon. لا يُعلن أن المستخدم يستطيع الدفع الحي الآن.
- المسار المؤسسي (استعلام/فاتورة/KYC) **يعمل** كمسار مبيعات لا كـ SKU ذاتي.

### 2.3 الأوركل

- الجملة الواحدة، الشرح، الشهادة، السجل العام، التوقعات المقفلة، بوابات الحقيقة (صافي الهامش / نصف العمر / نقض) **تعمل** داخل العملية.
- المجاني يحصل على 3 قرارات/يوم وعلامة مائية. هذا استحقاق كامل لطبقة Proof Pass وليس نقصًا.
- e2e المؤسسي **جزئي**: يستخدم أسعارًا حية وكتبًا؛ `learning_self_grade=false` (calibration stub). لا تُختلق نتيجة سوق لاحقة.
- درجة المصدر ولوحات الصدق **تعمل** كأسطح أمانة، وليست بائع بيانات حصري.

### 2.4 السوق

- صحة أسعار الكتالوج 100% **ليست** تغطية L2 مؤسسية. الفصل معلن.
- شبكة CORE: **92/92** كتب L2 حية — مكتملة لهذا النطاق.
- الكتالوج المؤسسي: **95/100** `venue_l2`؛ البقية `synthetic_mid` (AMM جوهري + bybit جغرافي). لا تُختلق كتب AMM كـ CEX L2.
- الرادار والشموع **تعمل** للمحترف+. المعنويات/السلسلة/الكلي **وكيلة عامة** — جزئية بصدق، ليست Kaiko/Glassnode.
- الخيارات نظرة عامة فقط، ليست OMS خيارات.

### 2.5 الأربتراج

- المسح الكانوني **يعمل** كاكتشاف. التنفيذ الحي مربوط بـ `live_fill` (محظور جغرافيًا).
- الكتالوج يخلط live/proxy/planned بصدق — لذلك `partial`.
- CEX↔DEX إشاري حتى تثبت التعبئة الحية.

### 2.6 التنفيذ

- المحاكاة وOMS الورقي وخزنة Fernet والتجميد والدورة التجريبية **تعمل**.
- `AUTO_EXECUTION_DRY_RUN=true` سياسة ملزمة: ليست مالًا حيًا.
- التعبئة الحية: المسار مسلّح بمفاتيح الاختبار؛ مضيفو الطلب يعيدون **HTTP 451**. الحالة `external_block` لا `broken`.
- Jupiter: التوقيع المحلي نجح؛ البث على السلسلة محظور بمحفظة غير ممولة (رصيد SOL=0).

### 2.7 المخاطر

- العمارة والسيولة تُستخدم في e2e. نطاق الحوت قد يعيد `whale_ready=false` عندما تضيق الكتب — هذا صدق لا عطل.

### 2.8 التنبيهات

- الصندوق الداخلي **يعمل** للجميع للقراءة.
- الاشتراك الحي لتيليغرام **جزئي** بدون `TELEGRAM_BOT_TOKEN`.
- جواز التنبيه المشروط بالدليل **يعمل** داخل العملية.
- سياسة السخاء سطح تنافسي صادق، ليست اتفاقية SLA لبائع.

### 2.9 الدفتر والبحث

- Journal CRUD على المجاني **يعمل** (كان مطلبًا سابقًا).
- المختبر والتقارير والدردشة وتحليل المحفظة **تعمل** لمن له الطبقة. المجاني لا يُوعد بها.

### 2.10 الأسطح الفريدة ونظام الثقة

- العدسات الأربع، الشرائح الست، F1–F10، الثمانية الفريدة، لوحات الصدق، الصندوق الزجاجي، نبض الثقة: **مشحونة**.
- `product_complete=false` على بيانات هذه الأسطح. الشحن ≠ اكتمال مؤسسي للمنتج كله.
- تقرير MEV استدلال وليس mempool خاص.

### 2.11 المنصة والتعلم الآلي

- نماذج محلية وتفسير احتياطي: **جزئي**. ليست مزرعة GPU مستضافة.
- بوتات الشبكة والقواعد والتقاويم والمشتقات: ألعاب داخل العملية + وكلاء عامون. ليست بيانات مؤسسية مدفوعة.

### 2.12 B2B

- التغذية بمفتاح بيئة **أو** مفتاح مؤسسة مجزّأ SHA-256 (`bd_org_`) **تعمل**. النص يظهر مرة واحدة.
- العلامة البيضاء: بوابة/طرفية/تصدير داخل العملية **تعمل**. النطاق المخصص متعدد المستأجرين **غير متوفر** ضمن سقف عدم الدفع.
- SSO/SCIM مسارات تشفير/CRUD موجودة؛ IdP الحي وBearer تشغيليان.

### 2.13 الصندوق والتشغيل

- طرفية الصندوق وبطاقة النموذج وغرفة البيانات **تعمل**.
- Postgres المحلي المتدفق: **VERIFIED_COMPLETE الوحيد**، مع `cloud_multi_az=false` صريح.
- cloud multi-AZ: حاجز خارجي مدفوع.
- الصحة والرصد Prometheus **يعملان** على العملية المحلية. هذا ليس SLA سحابيًا.

### 2.14 العناية الواجبة

- حزمة الأدلة تضم الحواجز الأربعة والحكم NOT COMPLETE. لا تُجمَّل للمستحوذ.
- قائمة الإطلاق/GTM **جزئية** إلى أن يضع المالك نطاق إنتاج وTLS وأسرار PSP.

### 2.15 الموقع والخصوصية

- الصفحات القانونية وPWA وOpenAPI وGDPR DSR **تعمل**.
- الامتثال التنظيمي **وضعية هندسية**، ليس ترخيصًا.
- GraphQL موجود لكنه ليس العقد الأساسي — `partial`.

## 3) التأكد أن القدرات تعمل بكفاءة كاملة (ضمن السقف الصادق)

«كفاءة كاملة» هنا تعني: المسار المستحق يصل، لا يُكسر، ويُفصح عن حدّه. لا تعني مالًا حيًا أو تغطية L2 100%.

### 3.1 ما تم التحقق منه في هذه المراجعة

| التحقق | النتيجة |
|---|---|
| جرد آلي فريد المعرّفات ≥ 70 | 89 قدرة، بدون تكرار معرّف |
| `product_complete=false` على الجرد والشرائح | ملزم |
| الحواجز الأربعة في JSON الجرد | `live_fill=false`، Jupiter VC=false، L2≠100، cloud_multi_az=false |
| `GET /api/product/capability-inventory` | 200، الحكم NOT COMPLETE |
| `GET /api/trial/persona-readiness` | 200، ست شرائح |
| `/settings/security` | 307 → `/profile` (لم يعد 404) |
| شبكة CORE L2 | 92/92 (موجة 7) |
| كتالوج L2 مؤسسي | 95/100 (موجة 7) |
| مفاتيح B2B على مستوى المؤسسة | إصدار/تحقق/تفويض يعمل |
| Postgres HA المحلي | VC الوحيد المعلن |

### 3.2 ما لا يُقال إنه «يعمل بكفاءة كاملة»

- تعبئة Binance الحية (451).
- بث Jupiter على السلسلة (محفظة غير ممولة).
- كتب AMM كـ L2 منصات.
- دفع Stripe/Lemon الحي بدون أسرار.
- تيليغرام الحي بدون توكن.
- SLA سحابي multi-AZ.
- علامة بيضاء كنطاق مخصص مستضاف.

كفاءة المسارات **الورقية والإثباتية والعامة** ضمن سقف عدم الدفع: **نعم**. كفاءة المال الحي والاكتمال المؤسسي 100%: **لا**.

## 4) التأكد من عدم نسيان أو توقف أو تعطل أي ميزة أو قدرة

### 4.1 عيوب منتج متوقفة داخليًا (كود مكسور نُسي)

**لا يوجد عطل منتج داخلي مفتوح معروف بعد هذه المراجعة** ضمن المسارات غير المدفوعة التي شُملت. القائمة الآلية `known_stopped_product_defects` فارغة.

إصلاحات سابقة كانت ستُحسب «نسيانًا» لو بقيت:

| كان | أصبح |
|---|---|
| `/settings/security` 404 | 307 إلى `/profile` |
| توجيه جمهور بأربع شرائح فقط | ست شرائح بما فيها B2B والمستحوذ |
| تغذية B2B بمفتاح بيئة فقط | مفتاح مؤسسة مجزّأ أيضًا |
| لا جرد آلي شامل لكل المجالات | `/api/product/capability-inventory` |

### 4.2 ما يبدو «متوقفًا» وهو ليس عطلًا

| الظاهر للمستخدم | التصنيف الصحيح |
|---|---|
| المجاني لا يرى أربتراج/تنبيهات/تنفيذ | `gated` — استحقاق Proof Pass |
| الحوت لا يملأ أمرًا حيًا | `external_block` — HTTP 451 |
| Jupiter لا يبث | `external_block` — محفظة صفر |
| الدفع لا يكتمل | `ops_config` — أسرار PSP |
| تيليغرام لا يُرسل | `ops_config` — توكن |
| SSO لا يدخل على IdP حقيقي | `ops_config` |
| WL بلا نطاق مخصص | سقف غير مدفوع |
| 5 خانات كتالوج `synthetic_mid` | سقف L2 غير مدفوع موجة 7 + طبيعة AMM |

خلط هذه الحالات مع «ميزة معطلة» كان سبب نقص التقرير الأول. هذا التقرير يفصلها.

### 4.3 أسطح HTML/API المشمولة ولم تُترك خارج الجرد

شملت المراجعة مسارات `dashboard.py` العامة، موجّهات `api/routers/*`، `platform_api.py`، الأسطح الفريدة F1–F10 والثمانية، عدسات Trust OS، الصحة، الخصوصية، GTM، الرصد، GraphQL، والتغذية المؤسسية. أي سطح تسويقي عام له صف في الكتالوج أو يندرج تحت صف تجميعي صريح (`WOW-CORE`, `WOW-F1F10`, `SITE-LEGAL`).

## 5) كل مستخدم — مهما كان مستواه — يحصل على القدرات المتوفرة له بالكامل

الاستحقاق يُقرأ من `TIER_FEATURES` + توجيه الجمهور + صفوف الجرد. «بالكامل» = كل ما صُنّف له في الطبقة/الشريحة، لا كل ما في المنتج.

### 5.1 مستخدم عادي صغير — `free` / Proof Pass / `audience=retail`

**يحصل بالكامل على:** أوركل 3/يوم، شهادة بعلامة مائية، سجل دقة عام، دفتر، MFA، قانوني/PWA/صحة، الأسطح الفريدة العامة، عدسة Prove، صندوق تنبيهات للقراءة.

**لا يُوعد بـ:** أربتراج، تنبيهات اشتراك، دردشة AI، تحليل محفظة، تنفيذ، تغذية B2B، حزمة أدلة.

حكم التجربة: **يحصل على طبقته كاملة.** الإغلاق ليس نقص توصيل.

### 5.2 محترف — `pro` / Decision Pro / `audience=pro`

**يحصل بالكامل على:** أوركل بلا سقف يومي، رادار، كتالوج أربتراج ومسح، مختبر، دردشة، محاكاة، اشتراك تنبيهات (المسار)، جواز التنبيه، تحليل محفظة، بوابات الحقيقة.

**جزئي/تشغيلي:** Checkout الحي، تيليغرام الحي.

حكم التجربة الورقية: **كامل.** الترقية المدفوعة الحية تحتاج PSP المالك.

### 5.3 حوت — `whale` / Decision Desk / `audience=whale`

**يحصل بالكامل على:** كل قدرات المحترف + مستشار التخفي + رادار الحيتان + صوت + MEV استدلالي + OMS ورقي + خزنة مفاتيح + تغذية B2B + حزمة أدلة (بدون ادّعاء COMPLETE) + تجميد طوارئ.

**لا يحصل (حاجز خارجي معلن):** `live_fill`، Jupiter VC على السلسلة.

حكم التجربة: **كامل لما هو مستحق بلا دفع.** التنفيذ الحي غير متوفر لأسباب خارجية مقبولة.

### 5.4 صندوق — sales-led / `audience=fund`

**يحصل بالكامل على:** طرفية الصندوق، غرفة البيانات، بطاقة النموذج، مؤسسات+RBAC+MFA، HA Postgres المحلي المثبت.

**جزئي:** SSO/SCIM بدون IdP/Bearer. **خارجي:** cloud multi-AZ.

حكم التجربة: **كامل لغرفة القرار والأدلة.** ليس أمين حفظ أصول ولا SLA سحابي.

### 5.5 B2B — `audience=b2b`

**يحصل بالكامل على:** مفتاح تغذية مؤسسة، JSON/WS، بوابة/طرفية/تصدير داخل العملية.

**لا يحصل ضمن السقف:** SaaS نطاق مخصص متعدد المستأجرين.

حكم التجربة: **كامل للاستحقاق غير المدفوع.**

### 5.6 مدير استحواذ — `audience=acquirer`

**يحصل بالكامل على:** حزمة الأدلة، إثبات الحواجز الأربعة، الجرد الكامل، لوحات الصدق، قائمة الإطلاق بوضعها الجزئي، الحكم NOT COMPLETE ظاهرًا.

**لا يحصل:** شهادة COMPLETE مزيفة. إخفاء الحواجز يُعد عيب أمانة لا «قدرة ناقصة».

### 5.7 خلاصة الاستحقاق

| الشريحة | هل تصل لها كل قدراتها المستحقة؟ | ماذا يُحجب بصدق؟ |
|---|---|---|
| تجزئة صغيرة | نعم | قدرات Pro+/Desk |
| محترف | نعم (ورقي) | شحن PSP / تيليغرام بلا توكن |
| حوت | نعم (ورقي/OMS) | تعبئة حية / Jupiter VC |
| صندوق | نعم (غرفة/أدلة/HA محلي) | multi-AZ سحابي |
| B2B | نعم (تغذية+WL داخل العملية) | نطاق مخصص مستضاف |
| مستحوذ | نعم (صدق DD) | شارة COMPLETE |

## 6) العيوب ونقاط الضعف إن وُجدت

مصنّفة حتى لا تُخلط عيوب المنتج بالحواجز الخارجية.

### 6.1 حواجز خارجية (مقبولة ضمن قيد عدم الدفع)

| العيب | الأثر |
|---|---|
| `binance_order_host_geo_451` | لا إثبات `live_fill` |
| محفظة Jupiter غير ممولة | لا VC على السلسلة |
| `zero_cost_no_paid_cloud_multi_az` | لا SLA سحابي متعدد المناطق |

### 6.2 سقف غير مدفوع (ليس اختلاقًا)

| نقطة الضعف | الأثر |
|---|---|
| L2 مؤسسي 95/100 | ~5 `synthetic_mid` (AMM جوهري + bybit جغرافي) |
| WL داخل العملية فقط | لا نطاق مخصص متعدد المستأجرين |
| وكلاء معنويات/سلسلة/كلي مجانية | ليست تغذية بائع حصري |
| نماذج ML محلية | ليست مزرعة تدريب مستضافة |

### 6.3 فجوات تشغيل المالك (الكود جاهز)

| نقطة الضعف | الأثر |
|---|---|
| لا أسرار PSP على البيئة | الترقية الذاتية لا تُشحن حيًا |
| لا `TELEGRAM_BOT_TOKEN` | تنبيهات Pro قد تبقى محاكاة |
| لا OAuth client ids | الدخول الاجتماعي لا يكتمل |
| لا ناقل بريد إنتاج | تحقق البريد / إعادة السر غير حيّين |
| نطاق إنتاج / TLS | الكوكيز/Checkout/golive معلّقة تشغيليًا |

### 6.4 ضعف منتج جزئي (صادق، غير مختلق)

| نقطة الضعف | الأثر |
|---|---|
| `learning_self_grade=false` في e2e | لا درجة ذاتية زمنية حتى نافذة سوق لاحقة |
| نظرة خيارات بلا OMS خيارات | عمق مشتقات محدود |
| GraphQL ليس العقد الأساسي | التكامل الأساسي REST |
| واجهة المستخدم الأساسية بالإنجليزية | الكتالوج i18n موجود؛ التجربة ليست عربية كاملة |

لا يُصنَّف أي من 6.1–6.3 كـ «المنتج نسي الميزة». 6.4 هي حدود عمق معلنة.

## 7) الأساسيات غير المتوفرة والضرورية

يُفصل الضروري حسب هدف الإطلاق. خلط «ضروري للتجربة» مع «ضروري للاكتمال المؤسسي» كان ثغرة التقرير الأول.

### 7.1 ضروري للإطلاق التجريبي الحي بلا دفع (ورقي/إثبات)

| الأساس | متوفر؟ |
|---|---|
| تسجيل/جلسة/MFA | نعم |
| أوركل + سجل دقة + شهادة | نعم |
| توجيه ست شرائح | نعم |
| جرد قدرات صادق | نعم |
| دفتر + أسطح فريدة عامة | نعم |
| OMS ورقي للحوت | نعم |
| حزمة DD بالحكم NOT COMPLETE | نعم |
| عدم ادّعاء COMPLETE | نعم |

**لا أساسي تجريبي ورقي ناقص يمنع الشرائح 1–2.**

### 7.2 ضروري للمال الحي (خارج سقف عدم الدفع / قرار المالك)

1. مسار طلب Binance من منطقة مسموحة **أو** بروكسي.  
2. تمويل محفظة Jupiter (SOL+USDC) **أو** مفتاح ممول.  
3. أسرار PSP حقيقية.  
4. نطاق إنتاج + TLS.  
5. توكن تيليغرام إن كانت التنبيهات الحية وعد إطلاق.

### 7.3 ضروري للاكتمال المؤسسي 100% (لا يُعلن قبلها)

1. cloud multi-AZ مدفوع (أو دليل مكافئ).  
2. كتب L2 حقيقية لما تبقّى — **دون اختلاق AMM كـ CEX L2**.  
3. (اختياري للصفقات B2B المستضافة) نطاق مخصص متعدد المستأجرين.

### 8.1 واجب ضمن سقف عدم الدفع (إن وُجد عمل متبقٍ)

| القدرة | الحكم |
